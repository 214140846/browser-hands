# output 模块规格

给 MCP 工具返回的文本加一道体积预算：估算 token、超限时截断并附上缩小范围的提示；另外提供一个「连续调用提醒器」，在模型反复做可合并的单步操作时，给结果追加一句提醒。全是同步纯逻辑，不碰浏览器、网络、文件。

## 1. 冻结的导出签名

| 导出 | 形态 | 参数 | 返回 |
|---|---|---|---|
| `DEFAULT_MAX_OUTPUT_TOKENS` | 常量 | — | `number`，值 `8000` |
| `estimateTokens` | 同步函数 | `s: string` | `number`（非负整数） |
| `maxOutputTokens` | 同步函数 | 无 | `number` |
| `truncateOutput` | 同步函数 | `text: string`，`max?: number` | `string` |
| `isBatchable` | 同步函数 | `name: string`，`input: any` | `boolean` |
| `makeHinter` | 同步函数 | 无 | `{ note(name: string, input: any, isError: boolean): string \| null }` |

只有这六个导出，不多不少。入参为字符串以外的 `text` / `s` 属未定义行为，调用方不得依赖。

## 2. estimateTokens

把字符串粗估成 token 数。规则按 UTF-16 码元计，每个码元独立归类：

| 码元 | 记为 |
|---|---|
| 值小于 128（含换行、空格） | 四分之一个 token |
| 值大于等于 128（中日韩、重音字母、表情等） | 一个 token |

总和向上取整。例：空串 → 0；4 个 ASCII → 1；5 个 ASCII → 2；2 个汉字 → 2；`ab你` → 2；一个表情符号占两个码元 → 2。同一输入永远得到同一结果，不依赖环境。

## 3. maxOutputTokens

读当前进程环境变量 `JEV_MAX_OUTPUT_TOKENS`（对外接口词，MCP 使用者靠它调上限）。

| 环境变量情形 | 返回 |
|---|---|
| 未设置、空串 | `DEFAULT_MAX_OUTPUT_TOKENS` |
| 十进制正整数字符串（如 `1234`） | 对应数字 |
| 无法解析成数字（如 `abc`）、解析结果为 0 | `DEFAULT_MAX_OUTPUT_TOKENS` |
| 负数、小数、科学计数等其他形态 | 未定义，测试不断言 |

每次调用都重新读环境，不缓存：调用方在两次调用之间改了环境变量，第二次要反映新值。

## 4. truncateOutput

`max` 缺省（`undefined`）时取调用瞬间的 `maxOutputTokens()` 结果；显式传入则以传入值为准、不看环境变量。

### 4.1 判定表

| 输入情形 | 可观察结果 |
|---|---|
| `text` 的估算值小于等于 `max`（含空串） | 原样返回同一个字符串，一字不改 |
| 估算值大于 `max`，且按行累计能保留至少一整行 | 见 4.2 |
| 估算值大于 `max`，连第一行都放不下 | 见 4.3 |

边界：估算值恰好等于 `max` 不截断；比 `max` 多 1 就截断。

### 4.2 按行保留

首行放得下时，返回值 = 原文开头若干整行（行间保持原来的换行，末行后不带换行）+ 一个空行 + 说明段（见 4.4）。

- 「行」按换行符 `\n` 切分，只在行边界截断，不会在行中间断开。
- 换行符也占预算：保留的行数要使「各行估算值之和，再加上各行之间被切分处的换行所占的一点点额度」不超过 `max`；怎么算由实现自定，以下面的例子为准。
- 例（每行 12 个 ASCII 字符，注意「估算为 3」指第 2 节的 token 估算值，不是字节数；共 6 行）：`max` 为 13 时保留 4 行，`max` 为 12 时保留 3 行。
- 例：三行各 40 个字符，`max` 为 15 时只保留第一行。

### 4.3 首行放不下

首行「放得下」的判定（整数 `max`）：首行的估算值严格小于 `max`。首行估算值大于等于 `max` 时按字符截取，不再按行。

按字符截取时，保留段是原文开头的一段前缀，长度只由字符的估算价决定，不受行边界约束（所以首行恰好顶到上限时，保留段可能延伸进第二行）。例：

| 输入 | `max` | 保留段 |
|---|---|---|
| 400 个 ASCII | 10 | 开头 40 个字符 |
| 50 个汉字 | 5 | 开头 5 个字 |
| 首行 40 个 ASCII，后接换行与更多内容 | 10 | 开头 40 个字符（恰为首行） |
| 首行 41 个 ASCII，后接换行与 `bbbb` | 11 | 首行 + 换行 + 2 个 `b` |
| 首行 36 个 ASCII，后接换行与 40 个 `b` | 10 | 只有首行（放得下，走 4.2） |

保留段之后同样接空行与说明段。保留段的估算值可能比 `max` 略多。此模式不保证不拆开代理对，测试不断言。`max` 小于等于 0 且文本非空：保留段为空，只剩说明；测试不断言。

### 4.4 说明段

位置：保留段之后空一行，作为返回值的最后一段。排版、措辞、标点、括号全部自定，测试不断言。必须出现的内容只有：

| 必须出现 | 用途 |
|---|---|
| 全文的估算 token 数（十进制整数，即 `estimateTokens(text)`） | 让模型知道原文多大 |
| 本次生效的上限数字（十进制，等于传入或默认得到的 `max`） | 让模型知道预算 |
| 环境变量名 `JEV_MAX_OUTPUT_TOKENS` | 告诉使用者怎么调高上限 |
| 工具名 `read_page`、参数名 `ref_id`、参数名 `max_chars` | 指引怎么缩小范围再取 |

说明段语言自定，是否提到其他工具自定。注意：对「上限数字」，测试只检查返回值里存在对应的十进制子串（如 `20`），不检查它出现的位置或前后文字。

### 4.5 其他

- 同步，无副作用，不改入参，不读写除环境变量之外的任何状态。
- 输入里已含类似说明的文字不做特殊处理，照常计价。

## 5. isBatchable

判断一次工具调用是否属于「可以和别的调用合成一次批量调用」的一类。永远返回 `boolean`，不抛错。

| 输入情形 | 结果 |
|---|---|
| `name` 属于下表「整个工具可批量」之一 | `true`，与 `input` 无关（`undefined` / `null` 也一样） |
| `name` 是 `computer`，且 `input.action` 属于下表「动作可批量」之一 | `true` |
| `name` 是 `computer`，`input` 缺失、为 `null`、无 `action` 或 `action` 是别的值 | `false` |
| 其他任何 `name`（即使 `input.action` 恰好是可批量动作） | `false` |

名称比较区分大小写。

整个工具可批量：`navigate`、`tabs_context_mcp`、`upload_image`、`gif_creator`、`resize_window`、`file_upload`、`tabs_create_mcp`。

`computer` 的动作可批量：`key`、`type`、`wait`、`left_click_drag`、`left_click`、`scroll_to`、`hover`、`right_click`、`triple_click`、`double_click`、`scroll`。

明确不可批量的例子：`computer` 的 `screenshot`、`zoom`；工具 `read_page`、`find`、`browser_batch`、`jev_task`。

来由：对外接口词（工具名 / 动作名）。

## 6. makeHinter

每次调用返回一个独立的提醒器，多个提醒器互不影响。同步。导入时无副作用。`note(name, input, isError)` 在每次工具调用结束后由上层调用一次，返回追加到结果末尾的提醒，没有则 `null`。

### 6.1 可观察行为：调用序列 → 何时出提醒

记「单调用」指提醒器收到的一次顶层调用；「点击」指 `computer` 的 `left_click` / `double_click` / `triple_click` / `right_click`。

| 调用序列（均未出错，`isError` 为假） | 结果 |
|---|---|
| 连续 2 次第 5 节判定为可批量的顶层调用 | 第 2 次返回批量提醒；提醒后「连续单调用」从头数，再来 2 次才再提醒 |
| 可批量调用之间夹了一次不可批量的顶层调用（如 `read_page`、`find`，或 `computer` 的 `screenshot` / `zoom`） | 连续单调用中断，不提醒 |
| 可批量调用之间夹了一次 `browser_batch` 或 `jev_task` | 连续单调用中断，不提醒 |
| 顶层 `computer` 点击 | **同时**计入「连续单调用」与「连续点击」两个计数 |
| `computer` 的 `wait` / `scroll` | 计入连续单调用；对连续点击既不增也不断 |
| `computer` 的 `screenshot` / `zoom` | 打断连续单调用；对连续点击不增不断（看一眼不算打断） |
| 点击之间夹了任何其他调用（`find`、`navigate`、`jev_task` 等） | 连续点击归零 |
| 连续点击累计到第 5 次 | 返回点击提醒；提醒后连续点击与连续单调用都归零 |
| 一次 `browser_batch`，其 `input.actions`（`{name, input}` 数组）里依次含若干子动作 | 子动作按上面同样的口径累计点击（点击 +1；`screenshot` / `zoom` / `wait` / `scroll` 不增不断；其他或畸形子动作归零）；`browser_batch` 本身打断连续单调用；累计到 5 及以上则立即返回点击提醒，数字为当时累计值（含之前攒的点击） |
| `isError` 为真 | 返回 `null`；不计入任何计数，也不打断任何计数 |
| `input` 或 `actions` 缺失 / `null` / 非数组 / 含 `null` 项 | 不抛错，按没有子动作 / 不可批量处理 |

典型例：
- `navigate`、`navigate`、`navigate`、`navigate`：第 2、4 次提醒，其余 `null`。
- `navigate`、`read_page`、`navigate`：全程 `null`。
- 点击与 `screenshot` 交替共 5 次点击：第 5 次点击提醒，数字 5，之前全是 `null`；之后重新累计。
- 一次 `browser_batch` 内含 7 次点击：点击提醒，数字 7。
- 4 次点击后插一次 `find`，再点 1 次：`null`。

### 6.2 提醒的种类与归零

| 提醒 | 触发 | 提醒后 |
|---|---|---|
| 点击提醒 | 连续点击达到 5 | 两个计数都归零 |
| 批量提醒 | 连续单调用达到 2（且此刻点击提醒未触发） | 仅单调用归零，连续点击保持（之后的点击继续往上攒） |

同一次调用既满足点击又满足批量条件时，只返回点击提醒（并两项归零）。一次调用至多返回一条。

两种提醒文本都整段被一对 `<system-reminder>` 标签包住（开标签在最前、闭标签在最后，协议约定，属接口）。点击提醒必须含 `quick_task` 与当前连续点击数的十进制数字；批量提醒必须含 `browser_batch` 且不得出现 `quick_task`。其余措辞、语言、长度自定，测试不断言。

### 6.4 常量来由

| 常量 | 值 | 来由 |
|---|---|---|
| 触发批量提醒的连续单调用数 | 2 | 项目自定：一次就提醒太吵，两次已能看出是在一步步做可合并的事 |
| 触发点击提醒的连续点击数 | 5 | 项目自定：连点五次基本是同一页面上的简单流程，值得整体委托给 `quick_task` |
| 换行占预算 | 很小的额度 | 被切掉的换行符不能白占位，具体额度以 4.2 的例子为准 |
| 默认上限 8000 | token | 项目自定：给模型上下文留余量的保守值，使用者可用环境变量调整 |
| 估算比率（ASCII 每 4 字符 1 token，非 ASCII 每字 1 token） | — | 业界常用的粗估口径，只求量级不求精确 |

## 7. 导入时副作用

无。不挂监听、不读写全局、不读环境变量（环境变量只在函数被调用时读）。

## 8. 边界清单

- `estimateTokens('')` 为 0；换行符按 ASCII 计。
- 未超限文本返回原对象值，字节级不变（含多行、含首尾空行）。
- 估算值恰等于上限不截断。
- 单行超限走按字符截取，保留段是原文开头的前缀。
- 环境变量在两次调用之间变化，`maxOutputTokens` 与默认上限的 `truncateOutput` 都反映新值；显式 `max` 优先。
- 错误调用（`isError`）既不提醒也不影响计数。
- `browser_batch` 的 `actions` 非数组、含 `null`：不抛。
- 测试不断言的：说明段与提醒文本的措辞排版（自定）、代理对是否被拆开、非正 `max` 的结果、负数 / 小数环境变量。
