# redact 模块规格

工具结果里会带出网址和页面标题，这些可能夹着登录令牌、签名、密码、会话号等机密。本模块负责：把网址里的机密部分换成占位符、判断标题是不是其实就是网址并照样处理、把文本安全地嵌进 JSON / HTML、清掉文本里的隐形控制字符和伪造的系统提示标签。全部是纯函数，无副作用。

## 1. 冻结的导出签名

| 导出 | 形态 | 参数 | 返回 |
|---|---|---|---|
| `redactUrl` | 函数 | `url: string` | `string` |
| `redactTitle` | 函数 | `title: string`, `url: unknown` | `string` |
| `escapeJson` | 函数 | `text: string` | `string` |
| `sanitizeText` | 函数 | `text: string` | `string` |

只有这四个导出，不多不少。四个函数的第一个参数应为字符串：传 `null` / `undefined` / 数字时抛 `TypeError`；其他非字符串（如 `URL` 实例、普通对象）为未定义行为，调用方不得依赖。`redactTitle` 的 `url` 不是可解析的网址（含非字符串）时视为「没有网址」。

## 2. 占位符

被抹掉的机密统一换成同一个占位符 `P`。`P` 由实现自定，要求：非空、只含字母数字（放进网址无需编码）、全模块固定不变、不含任何输入内容。下文「抹值」指把 `名=值` 变成 `名=P`；「整段抹」指把整段换成 `P`。

## 3. 判据定义

### 3.1 敏感参数名

判断前名字先百分号解码（`+` 当空格，解码失败按原文）。分词规则：除 ASCII 字母和数字以外的任何字符（`_`、`-`、`.`、`[`、`]`、空格等）都是分隔符；另外在「小写字母或数字」紧接「大写字母」处断开。所以 `product_code` 与 `product[code]` 的词都是 product、code，按末词规则都不因 code 敏感；`product[code]` 被抹只因下方方括号那一行把内层 `code` 脱离上下文单独判定。示例：

| 名字写法 | 词 |
|---|---|
| `api_key`、`API-Key`、`apiKey`、`api.key` | api、key |
| `X-Amz-Credential` | x、amz、credential |
| `ABCToken`（连续大写） | abctoken（连续大写不断开，只在小写或数字后接大写处断开） |
| `user2Pin` | user2、pin |
| `__key__` | key（分隔符不产生空词） |

词一律按小写比较。「末词」是最后一个词；「拼接名」是所有词无分隔连在一起。

下表从上到下列出各情形，满足任一「是」即为敏感名：

| 情形 | 是否敏感 | 例 |
|---|---|---|
| 末词是短敏感词，或末词去掉结尾 `s` 后是短敏感词 | 是 | `api_key`、`keys`、`sids` |
| 短敏感词只出现在非末词位置 | 否（除非下一行命中） | `key_id`、`pin_hint` |
| 拼接名包含任一长敏感片段（位置不限） | 是 | `myApiKeyValue`、`PHPSESSID` |
| 末词是 code，前一个词是业务编码前缀 | 不因 code 敏感（长片段仍可命中） | `zipCode`、`errorCode`、`key_code` |
| 名字形如 `外层[内层]`（`[` 不在开头），内层单独按本表判定为敏感 | 是 | `product[code]`、`data[sig]` |

短敏感词（必须是整词；类内按字母序）：

| 类别 | 判定原则 | 成员 |
|---|---|---|
| 一次性凭证 | 登录、验证、魔法链接里用一次就失效的值 | assertion、code、magic、nonce、otp、pin、totp |
| 认证 / 会话 | 直接证明身份或会话 | auth、bearer、jwt、key、sid |
| 签名与摘要 | 防篡改的签名、哈希、加盐 | hash、hmac、mac、salt、sig |
| 口令 | 口令的常见缩写 | pass、pw、pwd |
| 个人金融 / 身份 | 社保号、银行卡号与校验码 | cc、cvc、cvv、ssn |

业务编码前缀（与 code 组合时是公开的业务编号或状态码，不是验证码；类内按字母序）：

| 类别 | 判定原则 | 成员 |
|---|---|---|
| 商品 / 目录 | 商品、课程、活动等的编号 | article、catalog、category、course、event、item、job、model、part、plan、product、sku、type |
| 地理 / 区号 | 行政区、邮编、电话区号、机场码 | airport、area、city、country、dial、iata、post、postal、province、region、state、zip |
| 语言 / 货币 | ISO 语言、地区、货币代码 | currency、lang、language、locale |
| 状态 / 结果 | 协议或业务返回的结果码 | decline、error、exit、failure、http、reason、response、result、return、status |
| 键盘与外观 | 按键码、颜色码、尺码 | char、color、colour、key、size |

长敏感片段（拼接名包含即敏感；类内按字母序）：

| 类别 | 判定原则 | 片段 |
|---|---|---|
| 通用机密 | 名字直说是机密 | credential、secret、token |
| 口令 | 口令全称及变体 | passcode、passphrase、passw |
| 授权流程 | OAuth / API Key / SAML / Firebase 邮件动作码 | apikey、authcode、authkey、authoriz、oauth、oobcode、otpcode、saml |
| 签名 | 签名全称 | signature |
| 会话与防跨站 | 会话 id、Cookie、CSRF 令牌 | cookie、csrf、sessid、session、xsrf |
| 验证 | 验证码、校验器（verify / verifier / verification） | verif |
| 云厂商签名网址 | AWS `X-Amz-*`、GCS `X-Goog-*`、CloudFront `Key-Pair-Id` | keypairid、xamz、xgoog |
| 密钥 | 私钥、访问密钥 | accesskey、privatekey |
| 个人金融 / 身份 | 卡号、社保号全称 | cardnum、ccnumber、creditcard、socialsecurity |

### 3.2 像令牌的串（单词级）

「词」指只由字母、数字、`_`、`-` 组成的连续串。「字符类切换」指相邻两字符属于这三种之一：小写→大写、字母→数字、数字→字母（大写→小写、符号相关的不算）。

| 情形 | 是否令牌 |
|---|---|
| 长度 < 16 | 否 |
| 缺大写或缺小写字母 | 否 |
| 切换次数 < 3 | 否 |
| 切换次数 × 5 < 长度（平均不到每 5 字符一次） | 否 |
| 以上都不成立 | 是 |

例：`aB3dE5fG7hJ9kL1mN2` 是；`HelloWorldExample` 否（切换太稀）；全小写 / 全大写否。判定前先百分号解码。

### 3.3 像机密的值

值（解码后）满足任一：

1. 按「非字母数字下划线连字符」切开后，任一片是 3.2 的令牌；
2. 解码后长度 ≥ 24，且含一段 ≥ 16 位的纯字母数字串，这段里大写、小写、数字三类至少占两类（典型：十六进制摘要、Base62 随机串）。

短于 24 且非令牌形态的值不算（如 `hello`、`XYZ123`）。

### 3.4 值里嵌着网址

值（解码后）满足任一即视为嵌着机密：含 `//主机@` 形式的用户信息；按 `? & # ;` 切开后某段是 `名=值`（名非空、值至少 3 个字符），且名敏感或值像机密；含 `#` 时，`#` 之后不含 `=` 的段按 `/` 切开有任一段像机密。

## 4. redactUrl

### 4.1 按网址类型

| 输入情形 | 输出 |
|---|---|
| http / https | `协议//主机[:端口]` + 路径 + 查询 + 片段，各部分按 4.2 处理；**用户名密码丢弃**；主机按标准网址解析结果（小写、默认端口省略、路径按标准百分号编码） |
| 整串（不去空白）是 `about:blank` 或 `about:srcdoc`，大小写不限 | 小写形式 |
| `blob:` 且内层有来源 | `blob:` + 来源（如 `blob:https://a.com`），丢掉后面的 id |
| `blob:` 但来源为空（null 来源） | `blob:` |
| 其他带 `//` 的协议（ftp、ws、file、chrome-extension 等） | `协议//主机` + 路径（只做路径分号参数抹值），**查询和片段丢弃** |
| 其他可解析网址（mailto、data、javascript、tel、其余 about 等） | 只留协议，如 `mailto:`、`data:` |
| 不可解析 | 第一个 `?` 或 `#` 之前的部分，再按 4.3 编码截断 |

### 4.2 http / https 各部分

| 部分 | 输入情形 | 输出 |
|---|---|---|
| 路径 | 普通段（即使像令牌） | 原样 |
| 路径 | 分号参数 `;名=值` | 按 4.2 查询对的规则判，命中则抹值 |
| 查询 | 为空或只有 `?` | 不输出 `?` |
| 查询 | 按 `&`、`;` 切段，分隔符原样保留 | 每段独立处理 |
| 查询段 | `名=值`，值解码后 ≤ 2 个字符 | 原样（再敏感的名也不抹） |
| 查询段 | `名=值`，名敏感（3.1）或值像机密（3.3）或值嵌机密网址（3.4） | 抹值 |
| 查询段 | `名=值` 其余 | 原样 |
| 查询段 | 无 `=`，或 `=` 后全是 `=`（如 Base64 尾巴） | 去掉尾部 `=` 后像机密 → 整段抹；否则原样 |
| 片段 | 为空或只有 `#` | 不输出 `#` |
| 片段 | 有 `=`，且 `=` 在第一个 `?` 之前（或没有 `?`），如 `#access_token=…` | 整个片段按查询规则 |
| 片段 | 有 `?` 且其前无 `=`，如 `#/route/x?code=1` | `?` 前按 `/` 切段，像机密（3.3）的段整段抹；`?` 后按查询规则 |
| 片段 | 无 `=` 无 `?` | 按 `/` 切段，像机密的段整段抹 |

### 4.3 编码与长度

- 最终输出里空白字符（范围等同 JavaScript 正则 `\s`：空格、制表、换行、回车、换页、垂直制表、U+00A0、U+1680、U+2000–U+200A、U+2028、U+2029、U+202F、U+205F、U+3000、U+FEFF）、U+0085、`"`、`'`、`<`、`>`、`\`、反引号都按百分号编码（`'` 写作 `%27`），保证结果能安全放进引号、HTML 和 Markdown。
- 输入超过 16384 字符：只按前 16384 字符处理，且这部分末尾被截断的那个参数（最后一个 `? & # ;` 及其后）视为不存在，不出现在输出里。
- 输出超过 2048 字符：截短并在末尾加一个截断标记，总长恰好不超过 2048；标记文案实现自定，不得像网址的一部分，且标记最后一个字符不是字母或数字。

## 5. redactTitle

标签页标题常常就是网址本身（页面无标题时浏览器拿网址当标题），或包含网址的查询串。判定标题「携带网址」时返回 `redactUrl(某网址)`，否则原样返回标题。下表从上到下判定，先命中的行决定结果。

| 输入情形 | 输出 |
|---|---|
| 标题去首尾空白后是一个 http(s) 网址（中间无空白、可解析） | `redactUrl(去空白后的标题)`，与第二参数无关 |
| 第二参数不可解析 | 原标题 |
| 把标题当主机名看（去掉开头的 `协议://`，补上 http 解析）能解析、不含用户名密码，且主机名去掉开头 `www.`（大小写不限）后与网址主机名去 `www.` 相同、网址主机名非空 | `redactUrl(网址)` |
| 网址既无查询也无片段 | 原标题 |
| 标题长度 ≥ 4096 | `redactUrl(网址)`（太长无法可靠判断，按携带处理） |
| 网址的查询串（含 `?`）或片段（含 `#`）长度 ≥ 4、不超过标题长度的 9 倍，且原样或解码后出现在标题（或解码后的标题）里 | `redactUrl(网址)` |
| 其他 | 原标题 |

标题超过 16384 字符时只看前 16385 个字符做判断（多留 1 个字符，使超长网址标题交给 redactUrl 时仍会触发其输入上限截断与残缺参数丢弃）。

## 6. escapeJson

用于把 JSON 文本嵌进 HTML `<script>` 或按行切分的日志而不被提前截断。

| 输入字符 | 输出（六个字符的 JSON 转义，十六进制小写） |
|---|---|
| `<`（U+003C） | `\u003c` |
| `>`（U+003E） | `\u003e` |
| U+2028 行分隔符 | `\u2028` |
| U+2029 段分隔符 | `\u2029` |
| U+0085 下一行 | `\u0085` |
| 其他字符 | 原样 |

不变式：对合法 JSON 文本 `s`，`JSON.parse(escapeJson(s))` 与 `JSON.parse(s)` 深相等。空串 → 空串。

## 7. sanitizeText

清理将要交给 AI 代理的页面文本，防止页面伪造系统提示、用隐形字符藏指令。

| 输入情形 | 输出 |
|---|---|
| 成对的系统提示标签（开标签到最近的闭标签，可跨行，标签名大小写不限）及中间内容 | 整块删除 |
| 落单的开标签或闭标签（闭合 `>` 前可有空白） | 删除标签本身，保留周边文字 |
| C0 控制字符，但 `\t`、`\n`、`\r` 保留 | 删除 |
| DEL 与 C1 控制字符（U+007F–U+009F，含 U+0085） | 删除 |
| 零宽与方向控制：U+200B–U+200F、U+202A–U+202E、U+2066–U+2069、U+061C | 删除 |
| 行 / 段分隔符 U+2028、U+2029 | 删除 |
| 不可见格式字符：U+2060、U+FEFF、U+00AD | 删除 |
| 其他字符（含普通中英文、emoji、`<`、`>`） | 原样 |

「系统提示标签」指 Claude 对话协议里的 `system-reminder` 标签。标签内部夹了隐形字符的情形不作要求。

## 8. 常量来由

- 输入上限 16384：网址实际长度很少过万，过长多半是内嵌数据；先截断限住后面逐段解码的耗时。
- 输出上限 2048：沿用业界普遍的「网址不超过约 2000 字符」兼容上限，也控制回传给模型的长度。
- 值长度 ≤ 2 不抹：一两位的值（开关、页码、单字母）不可能是有效机密，抹了反而丢信息。
- 令牌最短 16、切换密度 1/5、长值门槛 24、混合段最短 16：常见随机令牌（Base62 / Base64URL / 十六进制）都在 16 位以上且字符类频繁切换；而自然语言单词、驼峰标识符切换稀疏。24 / 16 让 32 位十六进制摘要、UUID 去连字符等落入机密，而普通短 id 不误伤。
- 片段长度 4 与 9 倍（redactTitle）：短于 4 的 `?ab` 类碎片在普通标题里偶然出现概率高，不作为携带依据；查询串比标题长 9 倍以上时，标题不可能完整包含它，直接排除，省去对超长串的包含检查。
- 标题 4096：长到这个程度的标题已不像人写的，直接视作携带网址。
- `'` 单独编码为 `%27`：标准组件编码不处理单引号，而结果可能被放进单引号字符串。

## 9. 边界清单

- 空串 `redactUrl('')` → 空串；`escapeJson('')`、`sanitizeText('')` → 空串。
- 用户名密码一律丢弃，即使不像机密。
- 敏感名但值只有 1–2 个字符 → 不抹。
- 名字大小写、驼峰、下划线、连字符写法都视为同一名（`API-Key`、`apiKey`、`api_key` 同判）。
- 复数名：`keys`、`sids` 按 `key`、`sid` 判。
- `key_code`、`zipCode`、`errorCode` 不因 code 抹；`product[code]` 会抹。
- http 路径里的令牌形段不抹（只在片段里抹）。
- 非 http(s) 带 `//` 的协议查询与片段整体丢弃，不做逐参判断。
- 判定机密前统一百分号解码，`+` 视作空格；解码失败就按原文判。
